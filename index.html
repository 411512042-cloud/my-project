一、目前開發進度與架構實作

已完成 (Completed)

本週重點在於打通 LINE 官方通訊平台與自建後端伺服器間的「端對端雙向通訊管道」，完成從接收、解包、簽章驗證到自動回覆之基礎工程：

  • ✓

    LINE Webhook 事件接收端點 (/callback)

    以 Python Flask 框架搭建後端，並採用官方最新 line-bot-sdk v3，實作 WebhookHandler 與 ApiClient 事件分流機制。

  • ✓

    嚴密安全防偽驗證 (X-Line-Signature)

    於請求進入業務邏輯前，嚴格執行 HMAC-SHA256 簽章比對驗證，杜絕非法來源或未經授權的偽造 Webhook 呼叫。

  • ✓

    憑證安全隔離工程 (.env & .gitignore)

    落實資安最佳實踐，將 CHANNEL_SECRET 與 CHANNEL_ACCESS_TOKEN 完全抽離至 .env，並以 .gitignore 嚴格阻擋，防止金鑰外洩至 GitHub 公開倉庫。

  • ✓

    安全穿透隧道建置 (Cloudflare Tunnel)

    為克服 LINE Webhook 必須具備公開合法 SSL 憑證 (HTTPS) 的嚴格限制，自動配置並啟動 Cloudflare HTTPS 安全通道，映射本地 127.0.0.1:8000。

  • ✓

    基礎 Echo 雙向訊息驗證完成

    實作 MessageEvent (TextMessageContent) 處理器，使用者傳送文字訊息後，機器人可立即接收並成功回傳確認訊息。

三、目前待改善項目與後續開發挑戰 (Issues & Next Steps)

待進行 (In Progress)

雖然基礎通訊管道已全線暢通，但要達成計畫書中「有求必應的萬能個人助理」願景，仍有以下核心技術點待於下週依序克服：

  • !

    尚未整合 Google Gemini AI 模型核心

    目前機器人仍處於「測試 Echo 回覆」模式。後續需引進 google-genai SDK，注入全方位萬能助理 Prompt，讓其具備跨領域解答、英文地道潤飾與行程規劃能力。

  • !

    缺乏多輪對話上下文記憶 (Multi-turn Context)

    LINE Webhook 原生為無狀態（Stateless），使用者追問時機器人會遺忘上一句。需建立基於 user_id 的短期記憶快取機制（如 In-memory TTLCache 或 Redis），支援自然連貫問答。

  • !

    尚未加入多模態影像解析 (Vision OCR)

    尚未支援接收照片檔案（如傳送外文菜單、上課筆記或收據截圖），待整合 Gemini Vision 多模態串流解析能力，達成即拍即析。

  • !

    UI/UX 尚未卡片化 (Flex Message & Quick Reply)

    目前僅支援純文字回覆。後續需刻製精緻的 Flex Message 輪播卡片（如美食店家排版）與 Quick Reply 追問引導按鈕，並實作 Loading 動畫消除等待感。
